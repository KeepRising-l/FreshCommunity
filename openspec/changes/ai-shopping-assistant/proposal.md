# Proposal

## Why

平台的交易主线（开团 → 参团 → 成团 → 核销）与评价、通知能力已交付，但用户在"找团"环节仍依赖主动浏览：想买什么，只能自己去团购广场翻。同时，项目在开题阶段需要明确的技术研究亮点——目前全部能力均为传统 Web 应用形态，缺少可深入研究与演示的新技术要素。

本变更引入「AI 导购助理」：用大语言模型理解用户的自然语言购物需求，把"人找团"升级为"团找人"——用户一句话留需求（如"想要 10 元以内的苹果"），符合条件的新团出现时自动提醒；同时把已有的评价数据盘活为"口碑洞察"，为购买决策与提醒内容提供依据。

## What Changes

- **需求订阅与智能提醒**（主能力）：用户用自然语言描述购物需求，系统解析为结构化条件（商品关键词 + 价格上限）并保存；团长创建新团购时自动匹配订阅，命中即通过站内信提醒用户；创建订阅时立即扫描已有进行中的团购，命中即时提醒。支持订阅列表查看与取消。
- **评价洞察**（辅能力）：对评价文本自动分析，生成情感倾向与关键词标签；商品与团购详情展示口碑标签；订阅提醒消息附带口碑摘要（如"已有 3 人评价都说新鲜"）。
- **新增 LLM 调用层**：对接国产 OpenAI 兼容接口（配置化，可替换供应商），并内置规则解析降级方案——LLM 不可用时常见表述（"X 元以内的 Y"）仍可正常订阅，功能可用性不依赖外部服务。
- **数据库**：需求订阅表 `user_subscription`（第 8 张）已进入当前 schema；评价洞察阶段再新增 `review_analysis`（第 9 张）；`notification.type` 扩展 `SUBSCRIPTION_MATCH` 枚举值（表结构不变）。
- **明确不做**：多轮对话式交互（首版为单轮"一句话需求"）；自研模型训练；外部推送通道（仍为站内信）；订阅的复杂条件（品类树、时间窗、地理位置等）；不引入 Redis / 消息队列。

## Capabilities

### New Capabilities

- `ai-subscription`: 自然语言需求订阅与智能提醒 —— 一句话需求解析为结构化订阅条件、开团事件匹配、命中站内信提醒（含口碑摘要）、订阅查看与取消、LLM 不可用时的规则降级
- `review-insights`: 评价洞察 —— 评价文本自动分析为情感倾向与关键词标签、标签在商品/团购详情展示、分析失败不影响评价提交

## Impact

- **数据库**：当前 schema 已包含 `user_subscription`（user_id、关键词、价格上限、原文、创建时间）；评价洞察需新增 `review_analysis`；`notification.type` 增加枚举值，无需改表
- **后端**：新增 AI 模块（LLM 客户端 + 需求解析服务 + 订阅服务与控制器 + 评价分析服务）；`GroupBuyService.createGroupBuy` 挂订阅匹配触发（同事务或紧随其后）；评价提交路径旁挂分析触发
- **前端**：新增「AI 导购」页面（需求输入 + 解析结果回显 + 订阅列表）；商品/团购详情展示口碑标签；消息中心支持订阅提醒类型
- **外部依赖**：新增 LLM API 调用（可配置 base-url / key / model，默认建议国产 OpenAI 兼容接口）；无 key 或调用失败时自动降级为规则解析，演示与核心功能不受影响
- **无新增中间件**：不引入 Redis、消息队列；并发与一致性沿用现有数据库方案
