# FreshCommunity 界面设计方案（v1.0）

> 面向「社区生鲜团购平台」的全新 UI 设计。配套高保真原型见 [`prototype.html`](./prototype.html)。

---

## 1. 先看项目：它到底是个什么产品

**FreshCommunity** 是一个社区生鲜团购平台（毕业设计项目）。它的业务闭环非常清晰：

```
团长开团 ──→ 邻居参团下单 ──→ 人数达标成团 ──→ 到提货点自提核销
                    │
                    └──→ 截止未达标 → 自动解散 + 全额退款
```

三个角色、各自的核心诉求完全不同：

| 角色 | 打开系统最想干的一件事 | 对应的界面重心 |
| --- | --- | --- |
| **用户（邻居）** | 「有什么便宜的、快成团的？我要不要跟？」 | 团购广场 · 进度与倒计时 |
| **团长** | 「我这个团还差几个人？谁来提货了？」 | 我的团购 · 核销台 |
| **管理员** | 「今天卖得怎么样？商品库存还够吗？」 | 数据看板 · 商品管理 |

**关键洞察（决定了整套设计的重心）：**

1. **这是一个"决策驱动"的界面，不是"浏览驱动"的。** 用户不是在逛商城，而是在判断"这个团值不值得跟"。所以 **参团进度（8/12 人）+ 截止倒计时** 必须是最抢眼的两个元素——它们直接回答"还差几个人、还有多少时间"。
2. **"成团/解散"的不确定性是核心情绪。** 界面必须持续给出**确定性反馈**：进度条、还差几人、成团后的取货码、解散后的退款状态。
3. **取货码是全流程的终点凭证。** 它需要被"郑重对待"——大字号、票据化设计，而不是表格里一列灰字。
4. **核销是团长的线下动作，往往在嘈杂环境里单手操作。** 所以核销台要做成"专注模式"：大输入框、大按钮、极少干扰。
5. **现有实现是功能能跑但视觉裸奔。** 用的是 Element Plus 默认样式，没有品牌色、没有设计系统、没有空状态/骨架屏/加载反馈，`Home.vue` 甚至只有两行文字。本方案是从视觉语言到组件规范的完整重建。

## 2. 设计目标与原则

**一句话定位：让"跟不跟这个团"在 1 秒内被看懂。**

| 原则 | 含义 | 落地表现 |
| --- | --- | --- |
| **① 进度优先** | 一切服务"决策"，信息按决策价值排序 | 团购卡片上，进度条 + 倒计时占据视觉重心，价格紧随其后 |
| **② 状态透明** | 订单生命周期有 7 种状态，用户永远知道"现在到哪了、下一步是什么" | 彩色状态徽章 + 5 节点时间轴 + 下一步动作按钮 |
| **③ 新鲜可信** | 生鲜品类的信任感来自"看得见" | 大图商品位、评分前置、产地/提货点信息常驻、退款承诺明示 |
| **④ 邻里温度** | 区别于冷冰冰的电商 | 暖绿主色、圆润圆角、团长姓名与提货点始终露面、口语化文案 |
| **⑤ 角色自适应** | 三个角色看到的是三套导航，互不干扰 | 侧边栏按角色动态渲染菜单分组 |

**符合用户习惯的 8 条具体规则：**

1. 主色（绿）只用于"品牌/主操作"，强调色（橙）只用于"价格/紧迫/优惠"——两者不混用，用户扫一眼就知道哪里该点。
2. 价格用「¥ 小号 + 数字大号 + 划线原价 + 省多少」四件套，符合国内电商阅读习惯。
3. 倒计时进入最后 2 小时自动转为**红色 + 抖动感**，制造紧迫但可读。
4. 订单操作按钮永远出现在**卡片右下角**，且只显示"当前该做的那一个"主按钮（如"立即支付"），次要操作降级为 ghost 按钮。
5. 破坏性操作（取消、退款）用红色软底按钮，且不与主按钮相邻。
6. 所有列表都有**空状态、加载骨架、错误重试**三态（现版本完全没有）。
7. 表单即时校验 + 中文错误文案，不用 Element 默认的英文占位。
8. 数字全部使用 `tabular-nums` 等宽数字，金额、进度、取货码纵向对齐不跳动。

## 3. 信息架构与导航

**桌面端布局：左侧固定导航（236px）+ 顶栏（64px）+ 内容区。**

导航按角色分组，同一角色在不同场景下菜单不同：

```
用户 USER                    团长 LEADER                  管理员 ADMIN
├ 选购                        ├ 经营                        ├ 平台管理
│  · 团购广场                 │  · 我的团购                 │  · 数据看板
│  · 商品浏览                 │  · 核销台                   │  · 商品管理
├ 我的                        ├ 选购（同用户）              └ 我的
│  · 我的订单                 └ 我的（同用户）                 · 消息中心
│  · 消息中心
```

**为什么团长和管理员也保留"选购"？** 团长本身也是社区居民，管理员也需要查看前台效果；共用的"我的订单/消息中心"避免了三套割裂的实现。

**页面清单（11 个关键界面，原型内可切换）：**

| 分组 | 页面 | 设计重点 |
| --- | --- | --- |
| 基础 | 设计系统 | 色板 / 字阶 / 组件 / 圆角阴影 |
| 认证 | 登录 · 注册 | 左品牌叙事 + 右表单，注册可选角色 |
| 用户端 | 团购广场 | Hero 引导、筛选 chips、团购卡片网格 |
| 用户端 | 商品浏览 | 左侧分类 + 价格筛选、商品网格、评分前置 |
| 用户端 | 商品详情 | 大图、拼团价条、团购进度、评价、关联团购 |
| 用户端 | 我的订单 | 状态 Tab、订单卡片、**取货码票据**、状态时间轴 |
| 用户端 | 消息中心 | 五类事件图标化、未读高亮、一键已读 |
| 团长端 | 我的团购 | 经营 KPI、团购列表（差几人 / 核销数） |
| 团长端 | 核销台 | 专注式 6 位码输入、最近核销记录 |
| 管理端 | 数据看板 | KPI 卡、趋势折线、状态环形、最近订单 |
| 管理端 | 商品管理 | 搜索筛选、数据表格、库存可视化 |

## 4. 视觉语言（Design Tokens）

### 4.1 色彩

生鲜品类天然适合绿色，但纯绿容易廉价。方案采用**新叶绿（主）+ 暖橙（辅）** 的组合：

| Token | 值 | 用途 |
| --- | --- | --- |
| `--brand` | `#1E9E5A` | 品牌主色、主按钮、进度条、选中态 |
| `--brand-600/700` | `#178A4E` / `#12713F` | 悬浮态、深色文字、Hero 渐变 |
| `--brand-50` | `#EAF7F0` | 浅底、选中背景、徽章底 |
| `--accent` | `#FF7A1A` | **价格**、**倒计时**、优惠标签、支付按钮 |
| `--warning` | `#F5A524` | 评分星、库存偏低提示 |
| `--danger` | `#E5484D` | 退款、取消、紧急倒计时 |
| `--info` | `#3B82F6` | 待成团等中性进行态 |
| `--ink-900/700/500/400` | `#0F1A14` / `#33443B` / `#5B6B62` / `#8A9A91` | 标题 / 正文 / 次要 / 辅助 |
| `--bg` / `--card` | `#F3F7F4` / `#FFFFFF` | 页面底 / 卡片 |

> 中性色带**极轻微的绿调**（而非冷灰），这是让界面"有生鲜感"的关键细节。

### 4.2 字体与字阶

中文优先 `PingFang SC → HarmonyOS Sans SC → Microsoft YaHei`。

| 层级 | 字号 / 字重 | 用途 |
| --- | --- | --- |
| Display | 30 / 750 | Hero 主标题 |
| H1 | 22 / 700 | 页面标题 |
| H2 | 16 / 650 | 区块标题 |
| Body | 14 / 400 | 正文 |
| Caption | 12.5 / 400 | 辅助说明、时间戳 |
| Price | 20 / 750 | 价格（`tabular-nums`） |

### 4.3 圆角 / 阴影 / 间距

- 圆角：卡片 `16`、按钮与输入框 `9–12`、标签胶囊 `999`、Hero `20`。**整体偏圆润**，传递亲和力。
- 阴影：三级递进（`sh-1` 静置 → `sh-2` 悬浮 → `sh-3` 弹层），克制且柔和，避免 Element 默认的硬边。
- 间距：**8pt 栅格**（4/8/12/16/20/24/32/40），卡片内边距统一 `20`，卡片间距 `16`。

## 5. 关键组件设计

| 组件 | 设计要点 |
| --- | --- |
| **团购卡片** | 图片区（含"即将截止/新开团/已成团"角标）→ 标题 → 提货点与团长 → 价格四件套 → **进度条** → 进度元信息（已参团 X/Y + 倒计时）→ 主行动按钮。按钮文案随状态变化：「立即参团 · 还差 2 人」/「已成团 · 去提货」 |
| **订单卡片** | 头部（订单号 + 时间 + 状态徽章）→ 主体（缩略图 + 商品 + 提货点 + 金额）→ **取货码票据区**（虚线边框 + 6 个独立数字格 + 二维码）→ 5 节点状态时间轴 → 底部（提示语 + 操作按钮） |
| **取货码票据** | 独立浅绿虚线卡片，6 个 38×46 的数字方块，等宽字体，是整页视觉焦点之一 |
| **核销输入** | 6 个 60×74 的大号数字格，已填格变绿，当前格有 focus 光晕；下方"仅限本人团购 + 防重复核销"安全提示 |
| **状态徽章** | 圆点 + 文案，7 种状态各有配色：待支付(橙)/待成团(蓝)/待取货(绿)/已完成(灰)/已取消(灰)/已退款(红)/即将截止(黄) |
| **KPI 统计卡** | 44px 圆角图标底 + 26px 大数字 + 说明 + 右侧趋势标签（带 ↑↓） |
| **库存可视化** | 表格内嵌迷你进度条，低于 20% 自动转红并标注"偏低" |
| **空状态/骨架屏** | 统一样式：居中插画 + 一句中文说明 + 主行动按钮（本方案规范，实现时补充） |

## 6. 三端核心页面走查

### 6.1 用户 · 团购广场（首页）
顶部 Hero 用绿色渐变建立品牌感，右侧三个统计块（进行中/即将成团/新鲜在售）给用户"这里有货"的即时信心。下方筛选 chips 覆盖真实使用场景：**即将截止、马上成团**——这是用户最常用的两个筛选。卡片网格 3 列，进度条用橙色（>75% 时）或绿色区分紧迫度。

### 6.2 用户 · 我的订单
用状态 Tab 承载 7 种订单状态的归类（合并为 6 个 Tab）。待取货订单的**取货码票据**是重中之重；待支付订单给出**分钟级倒计时**（对应后端 30 分钟超时关单逻辑）；已退款订单直接说明原因（未达人数）。

### 6.3 团长 · 核销台
去掉一切干扰，只保留输入。大字号 6 位码 + 明确的安全边界说明（仅限本团、防重复），下方列出最近核销记录给团长"我刚做了几单"的确认感。

### 6.4 管理员 · 数据看板
对齐后端 `GET /api/admin/dashboard`（今日订单数 / 今日成团数），并在设计上**预留扩展位**：成交额、注册用户、7 日趋势、订单状态分布。图表用轻量手绘 SVG，不引入重型图表库即可实现。

## 7. 落地到现有代码

现有技术栈 **Vue 3 + Element Plus**，本方案可平滑接入，无需换框架：

1. **主题变量映射**：把上表 token 写入 Element Plus 的 CSS 变量覆盖文件（`--el-color-primary: #1E9E5A` 等），全站组件自动换肤。
2. **新建 `src/styles/tokens.css`**：承载全部设计 token，供自定义组件引用。
3. **抽出公共组件**（当前 `src/components/` 是空的，这正是首要改进点）：
   - `GroupBuyCard.vue` — 团购卡片（团购广场 / 商品详情复用）
   - `OrderCard.vue` — 订单卡片（含取货码票据、状态时间轴）
   - `StatusBadge.vue` — 状态徽章（状态 → 文案 + 配色的唯一映射源）
   - `StatCard.vue` — KPI 卡
   - `EmptyState.vue` / `SkeletonList.vue` — 空状态与骨架屏
   - `PageHeader.vue` — 统一页头
4. **重构 `Dashboard.vue`**：现在的侧边栏是平铺的 `el-menu-item`，改为按角色分组的导航（见 §3）。
5. **补齐状态映射**：订单 7 状态、团购 5 状态的中文文案与配色，集中在一个 `constants/status.js`，避免各处硬编码（现在 `UserOrders.vue` 直接展示英文 `status` 枚举）。
