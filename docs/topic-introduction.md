# 毕业设计选题介绍

> **课题名称**：社区生鲜团购平台的设计与实现（FreshCommunity）
> **课题类型**：应用开发型　**专业方向**：计算机科学与技术 / 软件工程
> **日期**：2026 年 10 月

---

## 一、选题背景

社区团购是近年快速发展的生鲜零售模式：以居住社区为单位，由「团长」发起生鲜商品的限时团购，居民集中下单、次日到社区提货点自提。相比传统电商，它具有**以销定采（降低损耗）、社区自提（降低履约成本）、邻里信任（降低获客成本）**三个结构性优势，已成为生鲜零售的重要渠道。与此同时，该模式对信息系统提出了不同于普通商城系统的特殊要求：

1. **成团机制的严谨性**：一笔交易是否成交，取决于截止时间前参与人数是否达标——系统必须精确管理「参团人数」与「截止时间」，并正确处理达标成团、到点解散、全额退款等分支流程；
2. **并发场景的可靠性**：生鲜商品库存有限、团购限时，存在多用户并发下单场景，系统必须防止超卖，并保证订单、库存、人数三者的一致性；
3. **多角色协作的业务闭环**：用户（下单）、团长（开团与核销）、管理员（商品与兜底）三种角色围绕同一笔订单协作，权限与流程必须清晰隔离。

## 二、选题意义

**应用价值**：本课题完整实现社区团购「开团 → 参团 → 成团 → 提货核销」的核心闭环，覆盖三角色全部业务流程，是一个可直接用于教学演示、也可作为真实社区团购系统原型进行二次开发的完整应用。

**技术价值**：课题聚焦几个有代表性的工程问题——**并发库存控制**（数据库原子扣减防超卖）、**订单状态机设计**（7 种状态与合法流转路径）、**数据一致性**（人数、库存、订单三者的对称回补）与**定时任务调度**（到期判定与超时关单）；并进一步引入**AI 导购**能力（大语言模型驱动的自然语言需求订阅与主动提醒），探索大模型技术在垂直电商场景中的落地方式。

**方法价值**：课题全程采用**规格驱动开发**（OpenSpec）：需求先于实现，每个功能都有可追溯的提案、验收场景与实测验证记录——这一过程本身即是软件工程方法论的一次完整实践。

## 三、主要研究内容

围绕三角色的完整业务闭环，研究并实现以下内容：

1. **用户与权限体系**：三种角色（用户 / 团长 / 管理员）的注册登录、JWT 无状态鉴权与角色权限隔离；
2. **商品与库存管理**：商品上架维护、图片上传；并发安全的库存扣减与回补机制；
3. **团购生命周期**：团长发起团购（成团人数 + 截止时间）、用户参团下单与模拟支付、人数达标提前成团、截止未达标自动解散退款；
4. **订单与核销**：订单 7 状态机、待支付超时关单、取货码生成与核销、管理员退款兜底；
5. **评价与消息**：已核销订单的商品 / 团长双维度评价与评分汇总；订单全生命周期站内消息通知；
6. **AI 导购（特色功能）**：用户以自然语言表达购物需求（如"想要 10 元以内的苹果"），系统解析为结构化订阅条件，在新团出现时自动匹配并主动提醒；解析链路支持大模型与规则两种模式、可降级切换；
7. **界面设计**：面向三角色的完整界面设计系统与高保真原型（桌面端 + 移动端）。

## 四、技术路线概述

- **后端**：Spring Boot 3 + MyBatis-Plus + MySQL 8 + Spring Security（JWT），分层单体架构；
- **前端**：Vue 3 + Vite + Element Plus + Pinia，前后端分离；
- **关键机制**：数据库原子扣减（防超卖）、条件更新（防重复成团）、定时任务（到期判定与超时关单）、状态机守卫（订单流转）；
- **AI 能力**：OpenAI 兼容大模型接口（可插拔）+ 规则解析降级，站内消息触达；
- **工程方法**：OpenSpec 规格驱动开发 + 实测验证（每个功能以真实运行系统的断言为完成标准）。

## 五、特色与创新点

1. **成团机制的完整实现**：人数一致性的对称设计（支付 +1 / 取消 −1 / 退款 −1），从机制上杜绝「虚假成团」（人数被已取消订单虚顶达成团条件）；并发达标用条件更新保证成团判定幂等；
2. **AI 导购的场景化落地**：把大模型能力嵌入真实交易链路（需求解析 → 订阅匹配 → 主动提醒），而非孤立的演示功能；解析走「大模型优先、规则兜底」的可降级设计，功能可用性不依赖外部服务；
3. **工程过程的完整性**：需求 → 设计 → 实现 → 验证全链路可追溯，具备完整的规格基线、设计文档、测试与实测报告。
